# План прогона ПМИ — Excel-агент ЕВРАЗ (первые 16 пунктов)

План прогона первых 16 проверок протокола приёмочных испытаний по ПМИ
(`technical_specification/ПМИ_ЕВРАЗ_v1 (2).docx`, приложение Б, пп. 1–16).
Каждый пункт ссылается на контрольный пример из приложения А ПМИ и на
конкретные команды/страницы проекта.

## 0. Предусловия (общие для всех пунктов)

- [ ] Стенд развёрнут: `docker compose up -d --build` (postgres, service, frontend).
- [ ] Модель подключена через `.env` (OpenAI-совместимый API, ключ только в `.env`).
- [ ] Эталонные файлы Заказчика загружены: `data/data_proportional_prices.xlsx` (+ Faked_List_proportional).
- [ ] Бенчмарк зафиксирован хэшем до испытаний (файл вопросов `docs/request_examples.txt`).
- [ ] Открыты: веб-интерфейс `http://localhost:8080`, API `http://localhost:8000/docs`, трейсы `/trace`.

> Порядок по п. 5.5 ПМИ: Д-1 → С → **Ф, П-1** → Н, Б → **К** → протокол.
> В этот план входят: Ф-1…Ф-13 (пп. 1–13) и К-1…К-3 (пп. 14–16).

---

## 1. Ф-1 — Загрузка и регистрация файлов (А-1, А-2)

- **Шаги (А-1):** загрузить `data_proportional_prices.xlsx` в UI (вкладка «Файлы»), открыть листы; загрузить файл повторно; сравнить хэш файла до и после.
- **Шаги (А-2):** поочерёдно загрузить: `.docx`, файл больше лимита, повреждённый `.xlsx`, книгу с пустым листом.
- **Критерий:** файл зарегистрирован, листы отображены, статус «успешно»; дубль не создан; недопустимые файлы отклонены с понятным сообщением; хэш исходного файла не изменился; 0 аварий.
- **Фиксация:** скриншот списка файлов + дубликата, хэши до/после.
- **Статус:** ☐ пройдено ☐ не пройдено

## 2. Ф-2 — Выбор данных для запроса / автоопределение листов (А-3)

- **Шаги:** 1) выбрать файл/лист и задать вопрос; 2) задать вопрос без выбора файла.
- **Критерий:** ответ построен по выбранным данным; во втором случае релевантные листы определены автоматически и указаны в источниках ответа.
- **Статус:** ☐ пройдено ☐ не пройдено

## 3. Ф-3 — Разбор сложного макета и нормализация (А-4)

- **Шаги:** загрузить синтетическую книгу (многострочная шапка, объединённые ячейки, пустые строки, итоги, ≥2 однотипных листа — `scripts/test_faked_ingest.py`); сравнить колонки с ручной разметкой; загрузить книгу той же структуры повторно.
- **Критерий:** колонки и типы совпадают с разметкой; пустые ячейки — NULL (не нули); в журнале/трейсе видно переиспользование разбора.
- **Статус:** ☐ пройдено ☐ не пройдено

## 4. Ф-4 — Подключение модели через конфигурацию (А-5)

- **Шаги:** изменить в `.env` идентификатор модели / temperature / таймаут; `docker compose restart service`; задать вопрос; `git status` (код не изменён).
- **Критерий:** ответ получен с новыми параметрами (по журналу/трейсу); код не менялся; ключ только в `.env`.
- **Статус:** ☐ пройдено ☐ не пройдено

## 5. Ф-5 — Расчёты всех типов по вопросу на русском (А-6)

- **Шаги:** пять задач демо Заказчика (lookup, max по листам, агрегат по группе, дельта, min по листам) — прогон `python benchmark/run_first5.py` (ответы совпадают с эталонами из `docs/request_examples.txt`).
- **Критерий:** все 5 ответов совпадают с эталонными значениями (текущий результат: 5/5, PASS RATE 100 %).
- **Фиксация:** `benchmark/results/run_first5_<timestamp>.json/.txt`.
- **Статус:** ☐ пройдено ☐ не пройдено

## 6. Ф-6 — Вычисления только через SQL, проверка и автокоррекция (А-7)

- **Шаги:** 1) открыть трейсы ответов А-6 (`/trace?request_id=…`, кнопка «Trace» в чате) — в каждом есть выполненный SQL; 2) запустить модульные тесты проверки SQL: `python -m pytest tests/test_codegen_helpers.py tests/test_agent_helpers.py -q` (SQL с ошибкой синтаксиса, к несуществующей таблице).
- **Критерий:** в каждой трассе есть SQL; некорректный SQL отклонён до выполнения, в трейсе — исправленный запрос (self-correction).
- **Статус:** ☐ пройдено ☐ не пройдено

## 7. Ф-7 — Сопоставление сущностей, итоги, единицы (А-8)

- **Шаги:** вопрос по категории «все виды медного лома» за период на листе с итоговыми строками.
- **Критерий:** значение равно эталону; SQL исключает «ИТОГО/ВСЕГО» (видно в SQL-блоке чата); единица измерения (руб/тн) указана.
- **Статус:** ☐ пройдено ☐ не пройдено

## 8. Ф-8 — Уточнение неоднозначного вопроса (А-9)

- **Шаги:** вопрос без периода: «Какая цена у поставщика …?».
- **Критерий:** задан уточняющий вопрос (status=waiting_for_input, варианты в UI) или ответ с явно названной интерпретацией.
- **Статус:** ☐ пройдено ☐ не пройдено

## 9. Ф-9 — История, SQL, источники, трасса шагов (А-10)

- **Шаги:** открыть ответ А-6, его трассу и историю диалога.
- **Критерий:** показаны SQL, листы, таблицы, колонки, шаги агента (classifier → planner → codegen → executor → verifier → answer) с входами, результатами и длительностью; вопрос есть в истории.
- **Статус:** ☐ пройдено ☐ не пройдено

## 10. Ф-10 — Таблица, линейный и столбчатый графики (А-11)

- **Шаги:** в чате: «Построй линейный график динамики цены … по месяцам»; затем «Построй столбчатую диаграмму … по поставщикам»; дополнительно — кнопка «Сделай график» под ответом.
- **Критерий:** табличный результат и оба графика построены (график по запросу и по кнопке); значения графиков равны табличным; для CLI — графики в файл.
- **Статус:** ☐ пройдено ☐ не пройдено

## 11. Ф-11 — Краткие аналитические выводы (А-11)

- **Шаги:** посмотреть текст ответа агента к графикам п. 10.
- **Критерий:** дан текстовый вывод о динамике/лидерах, не противоречащий результату (min/max, тренд).
- **Статус:** ☐ пройдено ☐ не пройдено

## 12. Ф-12 — Журнал запросов, воспроизводимость, удаление (А-12)

- **Шаги:** 1) открыть журнал по запросам А-6…А-11 (таблица query_log / MetricsPage `/metrics`); 2) удалить загруженный файл (кнопка «Удалить» в UI); 3) задать вопрос по нему.
- **Критерий:** все поля журнала заполнены (токены, хэш, версия промптов, статус, латентность); данные удалены, Система сообщает об их отсутствии.
- **Статус:** ☐ пройдено ☐ не пройдено

## 13. Ф-13 — Ход выполнения долгого запроса (А-13, ч.1)

- **Шаги:** задать многошаговый вопрос по нескольким листам (например, сравнение месяцев cross_sheet).
- **Критерий:** отображается ход выполнения (AgentProgress в UI), интерфейс не блокируется, повторная отправка не нужна. (Эмуляция сбоев модели — в Н-2, вне этого плана.)
- **Статус:** ☐ пройдено ☐ не пройдено

## 14. К-1 — Доля правильных ответов на бенчмарке Заказчика (А-16)

- **Шаги:** `python benchmark/run_all.py` на зафиксированном наборе (новая сессия на каждый вопрос).
- **Критерий:** PASS RATE ≥ **80 %**; отчёт в `benchmark/results/run_all_<timestamp>.json/.txt`.
- **Статус:** ☐ пройдено ☐ не пройдено (факт: ____ %)

## 15. К-2 — Доля правильных по каждому типу вопросов (А-16)

- **Шаги:** тот же прогон; разбить результаты по типам (lookup / max-min / агрегат / дельта / сравнение листов) из JSON-отчёта.
- **Критерий:** по каждому типу ≥ **80 %**.
- **Статус:** ☐ пройдено ☐ не пройдено (факт: ____)

## 16. К-3 — Результат относительно связок Заказчика (А-16)

- **Шаги:** сравнить PASS RATE прогона с результатами текущих связок Заказчика на том же бенчмарке (предоставляются Заказчиком).
- **Критерий:** доля правильных ответов не ниже **60 %** от результата связок / не менее 60 % абсолютных.
